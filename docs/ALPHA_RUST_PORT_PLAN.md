# 复用 AlphaBuild 逻辑，保持纯 Rust

2026-10-07，用户明确选择“坚持纯 Rust，移植其逻辑”。运行时继续采用Rust服务端，不引入C/C++对战核心、FFI或旁路游戏进程。AlphaBuild作为状态机、数据转换、资源装配与测试行为的参考；目标版本仍为3.3.3.3。

## 可复用性结论

3.3.3.3并非不能借助AlphaBuild。原生实现已经将内部游戏状态与客户端格式分离，模块边界可以沿用。此前的Rust认证、大厅、DATA加密、NCS CRC、快照字段表和输入解码继续作为本版协议边界，移植玩法时不再重复推导这些已验证部分。

本地参考README指定1.1.1.13。用户提示2.6.9.7已有修改后复用经验，但当前提供的loading-technical文档只涉及资源加载，未包含其服务端适配补丁。因此可以参考路线，不能直接估算3.3.3.3只需修改同样几个位置。

| 可沿用的边界/逻辑 | 本地参考源码 | 本版落实方式 |
| --- | --- | --- |
| 输入排队、时钟归属、每条命令执行 | `src/codol/player/codol_pmove_c1.h`、`src/codol/net/codol_usercmd_queue.*` | Rust输入队列与玩家状态拥有commandTime；快照时钟保持独立 |
| 玩法状态构造与线格式分离 | `src/codol/snapshot/codol_frame_builder.*`、`codol_engine_state.*` | 先构造Rust语义状态，再按3.3字段表编码；不直接复制C1字段向量 |
| 武器默认装配、附件合法性与模型映射 | `src/codol/weapon/codol_weapon_compose.*`、`src/codol/player/codol_bot_loadout.c` | 按本版实际资源表生成完整装配，不手选一组任意零件 |
| 射击、换弹、ADS、武器切换 | `src/codol/weapon/` | 分阶段补完整状态转换、计时、弹药守恒及事件；不是每帧重新填初始值 |
| 位移、地面、滑动、阶梯、姿态 | `src/codol/player/codol_pmove_c1*` | Rust移动核加明确的trace接口，逐项核对3.3的字段、标志和参数 |
| 碰撞、地图、脚本和AI | `src/codol/collision/`、`assets/`、`script/` | 后续独立模块；先打通单玩家可移动与命中，再扩展训练敌人 |

以上是复用结构和行为的实施路线，不代表这些模块已经移植完成。若直接改写参考代码，记录来源并保留其许可要求；本次架构评估没有把参考源码复制进Rust仓库。

## 已证实的适配工作

- 参考玩家字段表为244项，3.3静态提取为235项；例如C1当前武器offset0x33c，本版0x340。字段数量、偏移、标志和数组段必须由本版编解码适配。
- 参考武器资源固定部分为0xbfc字节，本版0x42e3b0复制0x38a个word，即0xe28字节。资源加载器和字段偏移不能原样沿用。
- 组合武器名格式也不同：参考解析item/variant成对参数，本版解析 `** base flag extra attachmentId...`，配件名称注册表与属性表再分开解析。
- 游戏DATA与大厅加密差异已有实测，见GAME_TRANSPORT_PROGRESS和AUTH_LOBBY_PROGRESS。不能以“改协议/版本常量”替代完整边界适配。
- 参考构建依赖32位x86工具链与保留汇编，附带exe为PE32。当前Mac PATH未发现其要求的NASM/交叉gcc；纯Rust路线无需为了链接该核心改变现有运行架构。

## 紧接着实施的单元

1. **默认装备配方**：参考 `CODOL_WeaponDeclaredDefaults` 的表驱动原则。本版优先核对 `coWeapItemswea.csv` 或其等价资源、分组部件表、注册ID、有效模型和附着点，再发完整组合名。旧版表路径不存在时追踪本版等价生产者，不能返回空配方当作成功。
2. **ADS连续状态**：由服务端保存输入目标、进度和过渡时间，使用真实武器参数；与开枪/换弹相互约束。当前右键预测动作不是ADS完成。
3. **最小移动核**：先实现可测试的命令时间推进与正常行走/地面碰撞，使用本版地图碰撞数据。没有碰撞时不以“修改坐标能动”宣称完成移动。

每单元都应有资源/目标代码依据、状态转换测试、真实客户端验收、独立Git提交。当前已完成的是鼠标转向、M4基础扣弹、空仓/主动换弹及手臂模型选择；默认配件、ADS、移动、碰撞和命中仍待实现。
