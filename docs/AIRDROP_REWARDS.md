# 空投奖励共用流程

普通空投 2、多箱空投 9、空投哨戒 4 和空投 SAM 22 共用本版标记弹、主武器投掷、运送、完整箱体扫掠、持续拾取及库存投影。阿富汗实机已确认专用空投4/22的运输机、落箱、拾取及转入16/21库存；对应设备和运输资源齐全时开放。2/9保留完整随机内容池，只在池内每个结果都有可用处理器和资源时开放。原生提示文字、进度条和完整表现尚未完成，不将四项列为完整验收完成。

本版阿富汗注册标记弹为 293 `airdrop_marker_mp`、294 `airdrop_mega_marker_mp`、295 `airdrop_sam_marker_mp`、296 `airdrop_sentry_marker_mp`。它们均为 grenade 类型、class 6、offhand class 0，爆炸半径为 0。真实资源给出拉栓 600ms、投掷 360ms、出手延迟 129ms、速度 960、向上速度 120，以及 31 种材质的平行和垂直弹跳系数。资源中的 fuse 字段为 1000ms，但空投启动不以该字段作倒计时。

主武器标记使用拉栓、保持、松键投掷和出手延迟状态；出手只消费一个武器弹药并生成一次投掷请求。事件使用本版 `EV_PULLBACK_WEAPON` 35 和最后一发事件 37；offhand 武器状态及事件保持独立。换武器或死亡取消尚未出手的动作，保留其弹药；未确认可用处理器的奖励不因标记武器存在而自动发放。

Marker 飞行复用普通手雷的世界碰撞、继承速度、重力和捕获材质系数。按 AlphaBuild 的 `airdropDetonateOnStuck` 机制，在停止运动后产生一次落点信号；不制造半径伤害。30 秒仍未停止运动的对象只清理，不伪造落点。该清理期限是本地保护参数。本版 timed-detonation 标志消费者、原生投掷动画和落点仍需独立核对。

AlphaBuild `_airdrop` 的公共控制流程包括按奖励实例追踪标记、在出手时提交权限、按空投类型选择运输机与内容、物理落箱、持续使用拾取及归属处理。其权重来自 `scr_airdrop_*` 配置，不能将本版统计表第 23 列的分类值冒充随机概率。完整资源、源指纹和诊断数据保存在忽略目录。

回归覆盖四种注册武器绑定、拉栓保持、出手延迟、一次投掷、死亡/切枪取消、继承速度、停止运动落点和无半径伤害。`marker-real-map-check.log` 使用匹配本版阿富汗资源及碰撞，四种标记均在投掷后约720ms停止运动并产生一次落点信号；该测试只证明服务端物理，不代替原生动画或完整空投验收。

当前模块归属：`game/rewards/airdrops.rs` 保存运输机和箱体状态，`game/modes/tdm/rewards.rs` 管理标记预留及出手提交，`transport/game/connection/input.rs` 和 `transport/game/connection/world.rs` 只桥接输入、落点和拾取。未出手切枪或死亡释放运输额度并保留奖励；已提交的标记按投掷时刻匹配落点。专用箱拾取转入哨戒/SAM库存；普通和多箱使用 AlphaBuild 的完整默认内容池，不删减未实现结果。可用性会逐项验证随机池，缺少其中任一结果的处理器时不开放。

运输机以完整旋转模型边界检查入场和离场航段；箱体以完整 AABB 连续扫掠地形三角形、地图刷体和动态实体，排除自身。箱体和运输预检采用已捕获的本版 `SHOT_MASK`，排除仅玩家限制体积；真实箱体落地高度有独立回归。该筛选是当前物理适配策略，未声称恢复本版原始箱体 clipmask。真实回归明确检查落箱高度，地形边缘另有中心射线无法覆盖的完整箱体测试。

持有者500ms、其它玩家默认8000ms的持续拾取要求范围、朝向、地图及动态物体视线、存活和生命编号一致；松键、失联、死亡及视角离开重置进度。完成票据绑定箱体编号、代次、领取者、生命和持有开始时刻。模式在验证票据后发放内容，发放成功才移除箱体；失败保留箱子，旧生命、到期、已消费及编号复用的票据不能再次发放。提示图标使用已捕获的 `killstreak_hint` 对 `ui_ksHint` 的 C1/C17 查询；完整文字、弹药箱提示、进度条和原生画面仍待验收。

本版普通F使用键的命令位为 `0x8`。隔离只读采样在持续按F期间观测到完整按钮字 `0x02000008`；桥接使用共享 `usercmd::BUTTON_USE`。只读采样覆盖运输机464..479及箱体480..543，原生已确认对应模型和非零DObj。

`pickup-native-results.json` 保存零起始5杀获得22/2/4、三个运输模型/箱体样本、拾取前后帧及真实库存。22的拾取将HUD动作转成21，4转成16；普通2保留完整默认抽签，已观察抽到额外16。按F持续拾取后箱体从原生快照删除，模式日志只提交一次发放。该验收证明链路与归属，不替代文字/进度、搬运、设备完整动作或所有随机内容的效果验收。

`mega-native-result.json` 记录零起始8杀获取9、运输机模型138的DObj438及四箱模型103的DObj439..442。四箱落地后，前三箱分别实际提交奖励1、5、12；后两项保存真实身份但不发布未完成效果的动作槽。自动导航使第四箱超过90秒期限，其消失属于到期清理，**不是成功领取**。报告逐箱保存 `grant_verified`，不以模型消失替代发放证据；第四箱完整领取仍待补验。

HUD按最近三种库存类型投影，超过三种的库存排队保留。已获得奖励的武器状态随槽位迁移；正在使用的标记和保存的主枪不会因拾取改槽而错位。拾到尚无处理器的真实内容仍保存身份和库存，但不发动作槽或激活武器。延迟消费检查库存实例及独立调用序号，HUD换槽或同一生命中取消后重试不会让旧回调消费新调用。
