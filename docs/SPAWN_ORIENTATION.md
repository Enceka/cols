# 原生出生朝向

本版TDM准备保留每个阵营、每个出生点的地图角度；首次出生和死亡重生使用同一个点的坐标与角度。正常23张地图的现有坐标、7500分和10分钟配置保持原值，角度由其只读地图实体资源补齐。源实体的三分量 `angles` 或单分量 `angle` 转为本版short角度；未定义角度按地图实体默认值0处理。地图变体过滤与出生坐标使用同一规则。

`tools/prepare_tdm_map.py` 生成平行的 `match_config.spawns` 和 `spawn_angles`。`game_map_starts` 剔除不适合真实胶囊的出生点时，同步剔除其角度。加载器拒绝数量不一致；Bot首次出生与普通重生也使用对应角度。隔离固定Bot验收在原点和原朝向重生。

玩家预测使用PS+0xa0／+0xa4／+0xa8的偏移，字段70／45／191、codec-100。消费者0x41af8e将原始usercmd角度与该偏移相加；0x5a192c..55从PS视角减去偏移，建立下一帧的原始输入基线。服务端在移动、射击和投掷中使用世界角度，在确认帧基线中保留原始角度域。回放和结算镜头使用自己的世界视角，不能借用玩家当前出生偏移。

死亡重生会重建客户端预测输入历史。服务端先发布新生命的坐标与朝向，再从首条确认该生命快照的命令校准一次偏移；之后正常鼠标转向保留，不反复锁住视角。该步骤同时覆盖负角度、跨360度和连续重生，避免累计偏移或沿用死亡前朝向。

Rust启动器下的只读原生验证已确认阿富汗／高楼Axis朝向180度、潜艇基地Axis270度和Allies90度，覆盖首次出生、普通鼠标转向、持有手雷导致的真实死亡、出生计数1→2及重生后再次转向。静态／协议、输入域、两队点位匹配及无效出生点剔除有独立回归。全地图角度准备不等于23图每个出生点都已逐点实机复核。

证据位于忽略目录 `research-output/spawn-native-20261014/`。`spawn-headings-prepared.json`记录23图来源、数量与坐标未改变的核对结果；`*-team*-verified.json`保留各原生样本的PS视角、偏移、出生点和鼠标转向。朝向验收没有使用截图、内存写入或客户端函数调用；Rust启动器管理客户端与本地服务，Python／C#仅作只读采样，窗口工具发送普通输入。
