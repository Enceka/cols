# Bot 单发狙击枪与第三人称动作

Bot 的实际射击经过与玩家共用的武器状态机。M200（`cheytac_mp`）实采参数为开火400ms、拉栓1100ms、退壳标记600ms；state6→7→0推进，等待未结束不能产生下一发，也不能只按AI的尝试频率扣血。

第三人称动作必须匹配当前武器的本版 `playerAnimType`／`weaponclass`。M200 的原生站立射击节点为595 `pt_rifle_fire`，换弹节点584 `pt_reload_stand_rifle`。更换诊断 Bot 的武器时，不能继续使用其原职业的自动步枪、冲锋枪或机枪动作配置。M200动作的本版animation_s+0x48实采时长为600ms；+0x40的30ms是初始插值时间。站立身体动作使用完整600ms，带有脚本duration覆盖的动作使用其指定时间（例如150ms），不统一缩短所有枪型。

`tools/prepare_bot_roster.py --rebind-animations` 为现有名单重新绑定当前武器动作，保留身份、服装、角色模型和其它配置。它要求本图、同客户端版本的只读角色和武器采集，拒绝缺失／歧义的动作；缺少拉栓枪身体动作时长的采集拒绝重新绑定；完整绑定成功后才替换内存中的名单，输出仍写到新文件。两种近战接触诊断的准备器会调用这个绑定路径，不生成枪械与身体动作不匹配的 M200 场景。

本版 `mp/playeranim.script` 的 sniper 开火分支使用595／596，移动分支没有独立上身开火动作；脚本未提供独立 `rechamber` 事件块。当前武器拉栓状态及事件已接，但完整第三人称手部／枪栓观感仍需复核，不能仅凭节点正确声称每种姿态已复刻。

验证：`research-output/bot-sniper-live-proof.json` 索引的实际射击和状态日志。全部11个Bot使用真实M200，保留所有射击间隔，最小1550ms；Bot4实读state6的400ms、state7的1100ms和退壳600ms。只读 原生状态采样 有88帧网络torso与原生torso lerp均为595，另有584换弹片段。`bot-sniper-full-clip-proof.json`记录配置600ms后的独立采样，原生595动作连续保持的采样窗口最高574ms，覆盖150ms以后的动作，非强制放慢动画速率。完整手部／枪栓和移动姿态仍需复核。

正常三图名单继续使用各自准备的职业武器；全M200短局仅用于独立诊断。普通换弹动作见 `BOT_RELOAD_PROGRESS.md`。
