# 原生玻璃破碎

服务器支持捕获世界碰撞中的原生可破碎玻璃。`ClientAssets.ExportCollision`读取36字节`cbrush`的`+2`字段：零为永久碰撞，非零值减一为玻璃编号，范围0..1023。静态依据为客户端`0x58993d/0x58994e`及`0x588f21/0x588f30`。没有编号的WINDOW碰撞仍然阻挡玩家、子弹和导航，不能依据contents位批量销毁。

`client_state.py --glass`只读导出玻璃系统`0x0297200c`的初始片数（`+0x14`）、52字节初始记录（指针`+0x5c`）、原点（记录`+0x10`）、面积位（`+0x2c`），以及`0x01a0fbd0`的1024条5字节网络状态。高楼捕获的169个初始对象与169个世界碰撞编号一一对应。资源及玩法证据见`research-output/native-glass-proof.json`。

客户端`0x43e070`在快照client records之后读取玻璃尾段。服务器使用稀疏格式：presence=1、sparse=1，每条11位编号、2位状态2、1位无命中信息标记0，最后是11位终止值1024。无命中信息是原生支持的`0xff`分支。`0x43dd40`只应用递增状态，状态2执行破碎。每个快照重发本局全部已破碎编号，完整帧、delta帧、重传和回放均保留当前破碎状态，不尝试通过回放恢复玻璃。编号须有序、唯一且有界，EOF及任意位对齐已验证。

世界几何与BVH保持共享且不可变；玻璃破碎位由每个连接独立持有。有效枪械射线只能击碎最近角色之前、永久墙体之前的玻璃，随后重新进行真实世界射线检查。队友仍阻挡子弹；近战击碎挡在刀刃前的玻璃并消耗本次命中，不同时伤害后面的角色。破碎后的对应碰撞不再参与胶囊、子弹、投射物及地面支撑检查。换背包和复活保留本局破碎状态，新对局重新使用完整玻璃。

导航可规划经过可破碎玻璃的地面路线；真实移动仍使用完整碰撞。Bot在近距离将路线上的玻璃作为瞄准目标，由正常持枪逻辑控制弹药、射击时序、第三人称动画及命中。视线可以穿过有原生编号的玻璃，但永久WINDOW体积仍遮挡。这里没有接入碎片伤害、爆炸碎窗、冲撞碎窗、裂纹状态或原生AI翻越动作。

原生高楼对局的只读捕获记录编号138、143同时达到incoming=2、applied=2，其余167块保持0；编号与正常Bot射击日志一致，全程0截图。普通数据、资源和证书已恢复，库存6772。鼠标自动瞄准未收敛，其失败记录保留在`highrise-glass-gameplay-retry/result.json`；玻璃状态证据来自独立只读采样，不能将该自动瞄准实验写为通过。玻璃应用状态证明不替代破碎画面、音效或高楼整图玩法验收。
