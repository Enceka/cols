# 近战与投射物

运行核心为纯 Rust，协议和资源以未修改的 3.3.3.3 客户端为准。独立刀具、完整近战吸附和投射物战斗仍未完成。

## 普通持枪近战

TDM 支持近战按钮 `0x4` 的上升沿，按当前枪械的真实持续时间、伤害延迟、收回时间和伤害推进 `13→14→15→0`。挥击只判伤一次，长按和重复命令不重复触发，不消耗子弹；打断换弹时不转移弹药。抬枪、切枪和菜单期间的按下不排队。旧训练靶诊断没有这一判伤链，保持关闭。

服务端在伤害时机使用真实位置、视角、存活目标、地图遮挡及比赛阵营，拒绝队友伤害、出生保护、已死亡目标和上一生命的迟到命令。当前判伤以原生64单位前方端点为基础，按中心、右上、左上、右下、左下顺序检测，四角各偏移视角right／up方向10单位，取第一个有效身体接触；队友接触阻挡且不受伤，每条射线独立检查世界遮挡。当前身体仍使用服务端粗包围盒，原生骨骼判定与完整刀具表几何未恢复。

有效刀杀进入死亡、尸体、计分、名片和历史回放链，不计爆头、不产生弹孔。击杀栏使用原生 MOD8（事件编码 908），回放保留实际持枪编号。

## 持枪近战接近移动

服务端接收原生 usercmd 的 yaw、distance 和 entity 提示，并独立验证站立、着地、当前敌人、阵营、地图遮挡和终点位置。候选沿提示yaw查找实际最近身体，不要求其与准星中心线相交；允许默认96单位范围内的侧向接近。原生枪械可以发送 entity=2047 且 distance 非零；该值表示没有显式目标编号，仍须由服务端找到并验证真实敌人。客户端提示不直接决定伤害。

- 距离不大于 64 时使用普通动作 8 及普通伤害延迟；大于 64 时使用冲刺动作 9 及冲刺延迟。
- 长距离分支要求采集到 WeaponDef+0x98 的非空动作名称和有效时长。缺少该元数据的旧采集仍可普通近战及短距离接近，不凭非零指针推断动作可用。
- 当前命令先执行移动，再设置 PM 标志 `0x10000`、朝向和距离；下一命令初始化速度 `2×距离/伤害延迟秒数`，按线性减速的中点速度推进。
- 移动使用原有胶囊、地面投影和 step-slide，不直接跳到客户端提示位置。计时结束、死亡、回放冻结及比赛结束清除接近状态。
- 原生会按完整移动子步积分；子步跨过计时终点时可能略超出名义距离。实采 75 单位提示在长命令下前进约 83.16 单位，客户端和服务端结果相符，不额外钳位到目标中心。

人物之间的完整动态碰撞、斜坡边缘及所有移动／姿态组合尚未完成原生一致性验收。客户端0x50a150／0x50a9d0／0x50aff0按身体投影与视野区域筛选候选。输入不携带cg_fov，服务端使用本版允许的最大90度构造筛选边界，水平／垂直半角正切上限0.5／0.375，并检查提示终点在真实身体15单位半径内。保留18单位脚高差限制；骨骼包围盒、目标优先级、特长与其它刀具行仍待核对。不能把这个校验边界当作完整原生候选排序。

## 本版字段与消费者

| 内容 | 本版位置／含义 |
| --- | --- |
| 武器类型 | WeaponDef+0x47c；bullet、grenade、projectile、riotshield、bomb、melee；+0x480 是武器类别 |
| 普通近战 | 总时长 +0x714、伤害延迟 +0x6f4、伤害 +0x6e0 |
| 冲刺近战 | 总时长 +0x718、伤害延迟 +0x6f8、动作名 +0x98 |
| 输入内存 | command+28 为浮点 yaw，+32 为距离字节，+34 为实体短整数 |
| PS 标志／计时／角度／距离 | 字段20/+0xc、148/+0x4b0、149/+0x4a8、150/+0x4ac |
| 快照编码 | 计时 -97；角度 -100，绝对分支为两个零位及 LE16 有符号角度；距离 8 位 |
| 动作阶段 | 0x426620、0x425f00、0x425c50、0x428df0 |
| 接近移动 | 0x41c9a0、0x41ca20、0x41cbd0；0x415bc0 投影地面 |
| 原生提示生成 | 0x45f260→0x50b8b0→0x50b530；0x50aff0 筛选候选；0x50a640 默认范围96 |
| 默认判伤几何 | 0x4b42f0／0xc66a54 五条射线；0x42dab0 范围64、0x42da50／0x42da80 偏移10 |

计时属于持续量，回放平移绝对时钟时保留其数值。原生秒数先存为 binary32，再乘 double 1000 截断为毫秒；角度解码会对短整数作符号扩展。

## 验证范围

`research-output/pose-tree-final-check.log`：361 项 Rust、52 项 Python、fmt/Clippy 通过。回归覆盖真实动作元数据、两种时间分支、唯一触发、重复命令、墙体阻挡、目标校验、快照位编码和跨过计时终点的原生移动向量。

`melee-wide-live-proof.json` 索引 `client-1791698973148` 的侧向接近：敌人在玩家前75、侧24单位，普通中心线不会命中；原生提示distance78、yaw62659被服务端接受，造成135伤害及100分刀杀。6个相同命令时间的健康、稳定、非回放位置样本最大单轴差约0.00001单位，弹匣仍为30发；样本不等于逐帧等价。原生候选区域采样仅使用local client0，CG指针槽号不作为AimAssist本地客户端号。

三图真实武器采集各含 194 条记录，保留原始文件；正常地图准备只更新对应 `arsenal_file`，保持 7500 分／600000ms。`charge-three-map-check.log` 使用当前玩家档案检查三图武器装配、接近快照、11 个 Bot 和注册槽位，快照 941 字节、线上包 949 字节。

`client-1791694333310` 的实机证据汇总为 `melee-charge-live-proof.json`：

- 6 次服务端接受的原生提示，距离为 75、94、69、75、61、80；短分支延迟 250ms，长分支 100ms。
- 75 单位诊断冲刺在保护结束后造成 135 伤害，击杀 Bot1，计 100 分；61 和 80 单位接近也有致命命中。更早的 75 单位接近被出生保护拒绝判伤，不能计为击杀通过。
- 6 个命令时间相同、健康、非回放且读取期间命令时间稳定的位置样本，最大单轴差 0.02112 单位；包含进行中与结束状态。保留全部配对及偏差，不代表每一帧预测都已等价。
- 只读采样包含原生动作 8／9、接近标志和计时；连续完成三局结算，其中首局阵营与诊断场景不符，不作为接近验证。

普通持枪近战另有 `melee-combat-live-proof.json` 的四次 135 伤害刀杀及败局结算证据。额外输入混合的片段不作为严格单次按键或弹药对照；动作观感见 `REVIEW_PENDING.md`。

## 投射物及剩余功能

即时命中弹道仅接受原生 bullet 类型，并保留特殊类别和标志约束。实际 `crossbow_mp`、`crossbowrare_mp`、`knifeballistic_mp` 都是 type2，不能按步枪／手枪类别接入子弹判伤。实际资源回归见 `projectile-type-captured.log`，没有把“排除错误子弹路径”当作投射物可玩。
