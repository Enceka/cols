## 公共档案真实闭环

`client-1791269648033` 的最后一条 8/3 参数共 1829 字节，服务端校验 zlib、32 KiB 解压长度及 CRC 后原子保存。下一次运行的 8/1 读取同一 AUTH UID/title 下的 public.bin。

独立 Python 使用 HKDF-SHA1 从该实验的握手 transcript 与私有 session key 派生密钥，核验重登 S2C HMAC、AES 解密后，确认：

- 返回记录 UID 等于认证会话 UID。
- 返回的档案参数（不含请求终止 0）、磁盘文件和原客户端上传逐字节一致。
- 保存参数 SHA-256：`f3313f27fd1fb2d421c64d2a7c90c48a7c6838bc51d7a9b932fa809233814e33`。
- 客户端没有再次循环请求公共档案，也没有 WIN_PROFILE_DOWNLOAD_FAILURE；后续继续到新玩家界面。

证明摘要在 `research-output/public-profile-relogin-proof.json`。真实档案和握手密钥仍在忽略目录，没有复制进 fixtures。此前文档中“公共档案实际闭环待验证”现已被本段证据替代。私有档案仍返回 800，装备改动/游戏进度的完整语义尚未验收。

## 在 Mac 上稳定读取客户端状态

新增 `tools/ReadClientState.cs` 和 `tools/client_state.py`：通过 GameHub 私有 prefix 内的 Mono/C# 编译器生成小型 Win32 工具，只使用进程查询和 ReadProcessMemory。**不调用 DebugActiveProcess，不注入线程，不写游戏内存**，避开之前 WineDbg 附加时的 WOW64 异常。

工具只查找当前 prefix 中唯一的 codoMP 客户端，验证研究副本标记与目标 EXE SHA-256，然后读取代码内固定的少量状态地址；没有任意地址转储接口，不读取会话密钥。运行前还核对实验 Unix PID、编译源码和工具二进制哈希。输出保存在当前实验目录。

```sh
# 在没有运行客户端时构建；使用项目私有 prefix，不需要 Parallels。
python3 tools/client_state.py --build

# 客户端运行期间，EXPERIMENT_JSON 替换为本次实验的路径。
python3 tools/client_state.py --experiment EXPERIMENT_JSON
```

独立 C# 编译结束后 Wine 有时已自行退出，wineserver -k 返回无输出的 1。构建工具允许这种情况，并用 -w 确认 prefix 服务结束；它持有实验锁，不能在活动客户端期间执行 --build。

新增 macOS 窗口工具只针对实验记录中仍在运行、路径匹配且带研究标记的 PID：

```sh
sh tools/build_game_window.sh
.tools/game-window EXPERIMENT_JSON info
.tools/game-window EXPERIMENT_JSON capture
.tools/game-window EXPERIMENT_JSON click X_FRACTION Y_FRACTION
```

坐标为整个窗口矩形的 0..1 比例；先检查截图再点。点击前必须激活该应用并确认事件访问可用；先移动真实光标（Wine 会读取 GetCursorPos），然后仅向目标 PID 发送事件。关闭的实验或 PID 复用会被拒绝。capture 使用 -o 排除窗口阴影，使截图和窗口矩形对应。

在 `client-1791271062210` 中，点击引导“继续”后观察到 21/5 请求。该任务可能用于训练对局服务器分配，精确参数/响应仍待恢复；本轮继续返回明确失败，未连接官方服务器或把原游戏进程当作已实现的 Rust 对战服务。
