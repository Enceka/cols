# 玩家角色外观与模型发布

玩家身体来自已校验公共档案的当前角色和换装，使用本版角色包、阵营／性别变体和本图空闲模型槽；尸体、回放与前三名保持同一身份。第一人称衣袖／手套使用原生角色组成，见[持枪模型](VIEWMODEL_PROGRESS.md)。

## 资源与身份

`characterClasses[0..11].slots[0..8]` 与 `currentCharacterIndex` 按public v233真实偏移读取，9个槽不是固定连续数组；fixture为 `character-slots-3.3.3.3.json`。`prepare_player_appearance.py` 生成27个角色包和940个可穿戴物品的必要元数据，保留来源摘要。

运行时校验所有权、允许成员、部件类型和冲突；包自带部件不要求单独购买。外观在本局冻结，换背包或保存名片不重用模型槽改变当前尸体／回放，新角色下一局解析。角色792的六部件和首个可玩帧第三人称已原生核对。

## 初始化和加载

模型名单进入初始gamestate，大消息使用本版zlib标志及受限展开，必要时分片；具体边界见[原生通道](NATIVE_CHANNEL_PROGRESS.md)。实际武器注册表去重重复配装，不能借重复configstring挤占资源槽。

部分Bot首个可玩帧仍采用原生备用人物，随后在约1.7～3.0秒完成自己的异步加载；玩家和部分Bot首样本已正确。当前未找到完整协议预热机制，不能推断官方流程必然如此，也不加固定等待或隐藏人物冒充解决。Bot外观见[阵营服装](BOT_OUTFITS_PROGRESS.md)。

## 验证与限制

自动验证覆盖非连续槽、当前角色、所有权、同类型覆盖、男女／阵营变体、缺失资源、注册复用与快照／初始化预算。`--characters` 和 `--appearance-load` 只读渲染器当前clientInfo、角色组成与加载状态，不用过期准备表当作实时对象。

原生衣袖／手套、尸体、个人／最终回放和结算链路已有证据。更多角色、复杂服饰、换装动作、完整逐图画面和首次加载继续专项复核，不能以模型编号或loaded状态代替视觉通过。
