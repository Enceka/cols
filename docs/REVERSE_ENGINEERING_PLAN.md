# 服务端重建范围与验证原则

目标为固定 CODOL 3.3.3.3 客户端与纯 Rust 后端，使用本地测试身份，不恢复腾讯账号认证。客户端沿用本机 Windows x86 程序，GameHub Wine/Proton 是已验证运行环境；Parallels 可用于对照。原始程序、账号和资源保留，研究在独立副本中进行。

认证、大厅、档案、库存、本地购买、房间、原生进图、权威团队对局和双客户端核心联机已具备对应实现。具体开放范围以[功能状态](REFERENCE_ALIGNMENT.md)、[地图覆盖](MAP_COVERAGE.md)和[连杀覆盖](KILLSTREAK_COVERAGE.md)为准。剧情任务、完整模式和装备对齐仍有缺项，不能称作全量复刻。

## 实现边界

- 服务端运行核心保持 Rust；AlphaBuild 提供状态机和行为线索，本版字段、地址、资源及传输独立核对。
- `protocol` 表达线格式，`content` 表达资源事实，`backend` 管理账号业务，`game` 管理权威玩法，`transport` 管理接入；依赖和所有权见[模块结构](SERVER_MODULARIZATION_PLAN.md)。
- 账号使用文件存储与共享写锁。购买扣款／授予保持原子提交，经验由独立事务保存进度和回执。
- 每个共享房间持有一份权威世界，各连接保留独立加密、输入、ACK 和复制历史。共享世界不能由单连接 ACK 驱动多次推进。
- 所有构建在本机完成，远端只部署运行；连接资料保存在私有忽略目录，不记录云主机地址。

## 证据要求

每项协议结论应关联固定样本摘要、方向、触发动作、字段编码、长度、消费者和置信度。VA、RVA、文件偏移分别标明，不能互换。反编译输出须与实际指令和调用链核对。

| 证据 | 能证明的范围 |
| --- | --- |
| 静态消费者与资源表 | 本版字段、入口、身份和候选规则 |
| 独立合成向量与自动回归 | 编解码、错误处理及受测业务行为 |
| 捕获地图的服务端模拟 | 真实资源下的移动、战斗及生命周期 |
| 原生只读状态与实际输入 | 客户端接受状态、操作与同步结果 |
| 画面、录音与人工体验 | 对应场景的视觉、听感和操作观感 |

自洽 roundtrip 不能替代独立向量；ACK 不等于玩法验收，菜单或加载画面不等于出生。测试通过不允许覆盖有效决策或降低证据标准。发现冲突时按 [AGENT.md](../AGENT.md) 判断描述过期、实现回归、测试错误或已授权行为变更。

## 待完成范围

共享多人需要逐项对齐单人 Bot 模式的背包切换、回放、经验及装备；完整模式、断线重连和公网 UDP 条件另行验收。连杀需要补齐各效果控制器及原生表现，Pro 和模式专用条目必须找到真实绑定。剧情目前限于关卡测试解锁、分配、资源初始化和采集，不能复用 TDM 作为剧情玩法。

枪械特殊状态、足部接触、翻越／梯子、完整结算演出、长时间稳定性和可迁移交付继续按[待完成清单](REVIEW_PENDING.md)推进。功能实现和需人工复核的项目分别记录，人工复核不阻塞独立工作。正常本地提交，不自动推送。
