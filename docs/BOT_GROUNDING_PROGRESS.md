# Bot 避让与地面接触

2026-10-11，3.3.3.3 原客户端与纯 Rust 服务端。

用户指出 Bot 移动似乎未贴地。本轮确认并修复一处原因：`BotController::separate_from` 原先只沿 XY 推开重叠角色，Z 不随坡面变化。上坡方向会被坡面挡住，下坡方向会使胶囊离开支撑面，再由下个物理步恢复。不是出生点修复失效，也不能通过统一降低所有 Bot 的模型高度处理。

现在避让先分类地面，将位移沿当前可行走坡面展开，再复用 `Motion::step_slide` 的胶囊滑动、台阶和近距离向下探测。空中避让仅滑动，不吸附下方平台；保存原速度和命令时钟，不额外运行重力。实际移动仍决定步行动画速度。

## 验证

- 新回归在旧实现上失败：上坡避让停在原位。修复后，brush 和 terrain 两种坡面、上下坡连续十次避让均保持支撑接触并产生有效位移。
- 墙面阻挡、空中上升/下降速度、时钟不变、离开平台不瞬移到远处地面、随后正常重力落地均通过。
- `bot-ground-check.log`：319 Rust、43 Python、fmt/Clippy 通过。新增的本地资源诊断默认忽略；探针和诊断后续调整另经构建、实采及 Clippy 检查。
- 三图各模拟 60 秒，固定随机种子，使用实际地图碰撞、配装和导航。修复后采得 Afghan 12431、安全屋 11166、坠机之地 12189 个存活状态，均未出现胶囊 startSolid。记录为 `research-output/bot-ground-*-after.json`；旧实现对照为 `*-before.json`。路径会因避让、交火和死亡发生分歧，不能把两组离地总数直接当作修复效果百分比。跳下台阶或平台时仍允许正常离地。
- 实机 `client-1791647562007` 已换回正常三图目录、7500 分/10 分钟配置。未修改原客户端、账号、背包或正常地图准备。

## 渲染脚部的只读核对

`--characters` 新增 `ground_pose`，只读 DObj 已计算的根和脚部骨骼。按本版 `0x4f9750`，要求 DObj+0x94 与骨架帧 `0x078b16c8` 一致，并检查 +0x74 的逐骨骼计算位；不调用客户端骨骼计算，也不把视野外残留矩阵作为脚部证据。跨帧读取标记为不稳定。

有效样本 `characters-1791647912973.json` 与实际地图碰撞复算得到 24 个当前脚部点，输出 `bot-feet-tdm-afghan-hud-state-live.json`。站立 Bot2 两个前脚骨骼距地约 0.64/0.11；跑步 Bot9 一脚约 9.14、另一脚约 -0.38，符合抬脚与落脚相位不同。跑步 Bot4 该帧两脚约 6.12/3.67，单帧不能排除正常腾空相位，也不能据此宣称持续悬空已完全消失。`j_ball_*` 是骨骼位置，并非精确鞋底网格。

首次探针把受保护的 pose 原点误作普通浮点，随后发现视野外骨骼矩阵也会残留；这些早期样本不计作通过。最终使用骨架帧与计算位门槛，并直接读有效骨骼根位置。此次只新增一张问题观察截图，验收主要依靠碰撞回归和只读采样。

本轮解决避让造成的错误离地，未实现服务端足部 IK，也未证明所有动作、坡度和台阶的视觉接触均与官方完全一致。后续如仍观察到持续悬空，应继续记录同一角色多个动画相位及脚下支撑面，不能把跑步抬脚强制压到地面。

本地诊断入口：`captured_bot_ground_contacts`，要求 `CODOL_GROUND_PROFILE` 为当前本地档案目录，`CODOL_GROUND_CAPTURE` 为简单输出后缀。可加 `CODOL_GROUND_POSES` 指向一次 `--characters` 捕获，只计算该图有效脚部与地面的距离，不重跑对局。

## 连续步态采样（2026-10-11）

新增 `tools/client_state.py --grounding`，每次至多10秒/200次采样。读取当前角色、腿/上身节点和原生 torso lerp 节点，脚部仍要求骨架帧与计算位有效。该模式不调用客户端函数、不注入、不产生截图。`CODOL_GROUND_POSES` 现在同时接受单次角色捕获和连续 frames 捕获。

正常 Afghan 实机 `client-1791649146611` 中，`grounding-1791649601994.json`、`grounding-1791649835218.json` 分别采164/157帧。与本图碰撞离线复算得到2924/3464个有效脚部点；输出 `bot-feet-tdm-afghan-hud-state-sequence1-masks.json` 与 `...-sequence2.json`。同时分别计算子弹/移动碰撞掩码的点射线，第一段2924点没有大于1单位的差异，本次现象不能归因于这两个掩码不同。

两段中连续双脚前部骨骼高于点射线地面2单位的最长观测约646/666ms（中间超过160ms无连续样本即断开）。不能将全部这类样本归为正常跑步腾空：Bot8在29543ms时双脚骨骼距地约20.01/18.70，而胶囊支撑差约0.32。它的根原点 `[3418.898,1846.441,57]` 位于地图brush2074/2075的侧缘；半径15的胶囊能碰到较高斜面，脚部点射线则落在旁边更低的地形。该处不是给人物加了统一Z偏移，也没有证据要求缩小原生胶囊或把人物整体压低。

因此上次避让修复仍有效，但物件边缘/复杂坡面的足底观感尚未彻底解决；需要继续核对路线是否过分贴边及原生足部姿态调整。本轮没有把探针增强当作第二项物理修复，也没有扩大“完全贴地”的验收范围。

## 导航捷径的地面支撑

后续发现独立导航缺陷：`Navigation::clear`只有抬高18单位后的胶囊前向扫掠，没有检查脚下是否存在地面。两块平台之间的深沟上方没有墙，因此被视为可走直线；近距离寻路、接入导航网格及转向时跳过拐点均可能选择这条空中捷径。合成深沟回归在旧实现上失败，见`navigation-gap-before.log`。

现在前向扫掠通过后，每隔至多12单位用原有站立胶囊检查线段附近的可行走支撑，允许18单位内的台阶/坡面变化；图边、路线两端连接与转向捷径共用同一检查。没有改变人物高度、胶囊半径、重力或客户端骨骼。此处是步行路线判断，不新增跳跃连接，也不把物件边缘足底问题宣称解决。

- 深沟回归改为绕行上层平台，转向不再抄近路跨沟；墙面绕行、双向台阶及地形坡面回归通过。
- `navigation-support-final-check.log`：340 Rust、50 Python、fmt/Clippy通过；新增实图诊断后另经fmt/Clippy复核。首轮坡面测试夹具缺少必填`surface_flags`，补齐后通过，原错误日志保留。
- `navigation-support-connectivity.log`：Afghan20、安全屋35、坠机22个出生点均可步行连通到对方首出生点；图节点/有向边数分别14123/100282、2251/13710、8354/51712。debug构建耗时约25.7/0.9/11.9秒；这不是优化版实机帧耗时。
- `navigation-support-three-maps.log`：三图各模拟一分钟，分别12311/10899/11970个存活状态，共35180个，均无胶囊startSolid。仍有正常空中下落；路线和战斗已变化，不将与旧轨迹的离地数量差当作视觉改善百分比。汇总`navigation-support-proof.json`。

本项的行为复核以路线、实际碰撞和实图连通性为准，未追加截图或宣称所有脚部动作已经贴地。
