# Bot 避让与地面接触

2026-10-11，3.3.3.3 原客户端与纯 Rust 服务端。

用户指出 Bot 移动似乎未贴地。本轮确认并修复一处原因：`BotController::separate_from` 原先只沿 XY 推开重叠角色，Z 不随坡面变化。上坡方向会被坡面挡住，下坡方向会使胶囊离开支撑面，再由下个物理步恢复。不是出生点修复失效，也不能通过统一降低所有 Bot 的模型高度处理。

现在避让先分类地面，将位移沿当前可行走坡面展开，再复用 `Motion::step_slide` 的胶囊滑动、台阶和近距离向下探测。空中避让仅滑动，不吸附下方平台；保存原速度和命令时钟，不额外运行重力。实际移动仍决定步行动画速度。

## 验证

- 新回归在旧实现上失败：上坡避让停在原位。修复后，brush 和 terrain 两种坡面、上下坡连续十次避让均保持支撑接触并产生有效位移。
- 墙面阻挡、空中上升/下降速度、时钟不变、离开平台不瞬移到远处地面、随后正常重力落地均通过。
- `bot-ground-check.log`：319 Rust、43 Python、fmt/Clippy 通过。新增的本地资源诊断默认忽略；探针和诊断后续调整另经构建、实采及 Clippy 检查。
- 三图各模拟 60 秒，固定随机种子，使用实际地图碰撞、配装和导航。修复后采得 Afghan 12431、安全屋 11166、坠机之地 12189 个存活状态，均未出现胶囊 startSolid。记录为 `research-output/bot-ground-*-after.json`；旧实现对照为 `*-before.json`。路径会因避让、交火和死亡发生分歧，不能把两组离地总数直接当作修复效果百分比。跳下台阶或平台时仍允许正常离地。
- 实机 `client-1791647562007` 已换回正常三图目录、7500 分/10 分钟配置。未修改原客户端、账号、背包或正常地图准备。

## 渲染脚部的只读核对

`--characters` 新增 `ground_pose`，只读 DObj 已计算的根和脚部骨骼。按本版 `0x4f9750`，要求 DObj+0x94 与骨架帧 `0x078b16c8` 一致，并检查 +0x74 的逐骨骼计算位；不调用客户端骨骼计算，也不把视野外残留矩阵作为脚部证据。跨帧读取标记为不稳定。

有效样本 `characters-1791647912973.json` 与实际地图碰撞复算得到 24 个当前脚部点，输出 `bot-feet-tdm-afghan-hud-state-live.json`。站立 Bot2 两个前脚骨骼距地约 0.64/0.11；跑步 Bot9 一脚约 9.14、另一脚约 -0.38，符合抬脚与落脚相位不同。跑步 Bot4 该帧两脚约 6.12/3.67，单帧不能排除正常腾空相位，也不能据此宣称持续悬空已完全消失。`j_ball_*` 是骨骼位置，并非精确鞋底网格。

首次探针把受保护的 pose 原点误作普通浮点，随后发现视野外骨骼矩阵也会残留；这些早期样本不计作通过。最终使用骨架帧与计算位门槛，并直接读有效骨骼根位置。此次只新增一张问题观察截图，验收主要依靠碰撞回归和只读采样。

本轮解决避让造成的错误离地，未实现服务端足部 IK，也未证明所有动作、坡度和台阶的视觉接触均与官方完全一致。后续如仍观察到持续悬空，应继续记录同一角色多个动画相位及脚下支撑面，不能把跑步抬脚强制压到地面。

本地诊断入口：`captured_bot_ground_contacts`，要求 `CODOL_GROUND_PROFILE` 为当前本地档案目录，`CODOL_GROUND_CAPTURE` 为简单输出后缀。可加 `CODOL_GROUND_POSES` 指向一次 `--characters` 捕获，只计算该图有效脚部与地面的距离，不重跑对局。
