## 胶囊碰撞的补充修复

原实现是盒体，坡面支撑距离使用各轴半尺寸之和；客户端使用垂直胶囊，二者在坡面可相差数个单位。现使用radius=min(15,height/2)、圆柱半长=height/2−radius；刷体支撑距离为radius+abs(normal.z)*圆柱半长。原生参考cm_trace.cpp的2965/2130附近有相同形状/支撑公式，目标结构布局仍独立提取。

地形使用胶囊中心线到三角面的最近距离和连续保守推进，覆盖面、边、顶点及球帽/圆柱，并保留BVH。新增高速、边缘、圆柱、共面接缝与静止坡面回归，移动模块14项测试通过。0.25坡面的理论胶囊偏移约0.462，旧盒体偏移3.75，测试不再以盒体偏移作正确基准。未声称静态模型、动态实体和原生mesh border过滤已恢复，胶囊扫掠间隙按本版`0x586810/0x58bb50`消费的`0xc855d0`常数使用0.125；原生接触面、起扑高度阈值及接地帧次采用同一间隙。

最新真实账号运行 `client-1791425491792`：坡面静止时客户端/服务器三个坐标完全一致；同指令时间的256个移动样本中位位置差0.09378单位、最大2.60924，停止后差为零。实际camera yaw−65.66528与render294.33472一致。相机/落地/注册修复和胶囊实现均已通过实机局部验证，用户随后实机确认“已经明显顺畅”。特殊地形仍可能有边界差异。

复现备用模式测试可用gamehub_run.py的 `--service-data-dir` 指向独立诊断副本；原账号没有为了这次测试被换成诊断配装，最终运行恢复 `client-work/server-data`。
