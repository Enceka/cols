# 拾荒者补给

纯 Rust 在有效非自杀击杀后生成补给包，存活且装备拾荒者的玩家接触时自动拾取。当前枪必须有可补充的备弹空间；只有副枪或投掷物不足不能通过资格检查。死亡、回放期间和满备弹状态不消耗包，成功拾取一次后删除实体。

本版 `specialty_scavenger` 为物品60040／能力2，预测PS+0x4cc的位0x20000000。表中该能力为标志，数值可以为0；资格使用实际装备的能力集合。

## 本版原生路径

`fixtures/protocol/scavenger-3.3.3.3.json` 来自固定客户端和只读注册表 `weapon-registry-1791729022220.json`。`tools/prepare_scavenger.py` 同时核对 PE 的 ITEM 字段表和运行态触碰常数。

- 实体为 ITEM3，字段表 `0xc543b8` 共61项。ES+0x98按 `weapon + 900 × modelSlot` 编码，本包为229／slot0。
- `0x501320` 直接读取 WeaponDef+0x18 的模型指针；实际 DB type4 名为 `weapon_scavenger_grenadebag`，不能用 GENERAL 的模型NCS编号替代。scale=1，位置为静止轨迹，owner=2047。
- `0x412600` 的差值为玩家位置减包位置，X/Y各在[-36,36]，Z在[-88,18]。四个常数均是float64；运行态与静态值相同。服务器使用与原生signed16位置编码一致的包坐标。
- `0x4128c0`／`0x4126d0` 检查拾荒标志、当前枪和原生弹药余量。当前支持普通储备弹药枪械；clip-only、充能及特殊武器分支未完成。
- 拾取使用主PS可预测事件16，param229。原生按预测序号和事件ID抑制该事件的回声；不附加第二事件通道或额外声音命令。四个真实拾取声音槽均为 `grenade_pickup`。

实体使用1740..1799独立编号，并在烟雾之后、击杀栏事件之前编码。满帧、已确认delta基线、显式删除、编号复用与回放历史均保留真实包状态。复用按每个编号切换重置位；结算清除现场包，最终回放仍可读取对应历史。

## 补给和上限

掉落、每次增加一个弹匣及投掷物补给语义参考工作区 Alpha/LAN `_weapons.gsc:825..894`，不称本版官方生产脚本已经恢复。当前储备池按实际ammo key去重，主／副枪与备用模式共享的池只补一次并同步；组容量不足时先补当前持枪。标准破片、短引信破片和Semtex不补，其它已支持配方的offhand数量加1并按本版容量钳位。

容量采用本版 `0x429d20`／`0x429e50`／`0x429f20`：同ammo key的持有枪贡献相加，WeaponDef+0x6c4在+0xdac非零时乘弹匣容量；+0x6d0为非负共享组时使用+0x6d4，并扣除同组真实库存，储备池按key去重。已有模式别名不增加一次持有枪贡献。当前实际组合主枪为30×6=180备弹，副枪为15×6=90备弹；出生时3个弹匣和协议2047上限都不能替代原生容量。完整模式／技能对容量的修正仍有缺项。

短暂图标采用本版 `scavenger_pickup` 材质及现有原生MATERIAL HUD。每张地图独立计算NCS顺序并绑定CRC；当前三图为slot161。参考脚本的默认第一人称位置为x=-36／y=32、64×32、2500ms淡出，与命中反馈共用一个展示槽，不额外排入命中音。

当前静止落地、最多16包、30秒寿命、场内初始1秒不掉包是有界服务器策略；原生生产的抛落物理、寿命和可见性筛选尚未恢复。

## 验证

`scavenger-live-proof.json`：隔离安全屋实验 `client-1791729497100`，400帧中341帧读到补给包及正确DObj；两次重生后接触已有死亡包，时刻9449／17399，原生备弹从90／45恢复到120／60，战术数量恢复至2。96个玩家普通视角样本为材质161、正确位置／尺寸及2500ms淡出；首个事件在原生主环中为sequence9／ID16／param229，首次图标在11972清零。后续服务端连续补给达到180／90上限。此证据不声称玩家主动击杀、独立听感或所有回放组合都已验收。本项未使用截图。

回归覆盖无技能、满弹、当前枪资格、死亡拒绝、触碰边界、一次消耗、真实组余量、共享模式去重、战术数量、出生保护／自杀不掉包、包寿命／编号复用、各bit-pool对齐、指定基线删除和回放历史。完整检查见 `scavenger-final-check.log`。
