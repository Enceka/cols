# UAV 与反侦察机

目标为未修改的 3.3.3.3 客户端与纯 Rust 服务端。阿富汗通过 `radar_file` 启用两种普通电台奖励；其它普通奖励保持图标／门槛预览，不发布没有处理器的可用动作。

| 奖励 | 原生 ID | 商城物品 | 基础击杀数 | 阿富汗武器 |
| --- | ---: | ---: | ---: | ---: |
| UAV | 1 | 60076 | 3 | 329 |
| 反侦察机 | 3 | 60078 | 4 | 314 |

`tools/prepare_radars.py` 从初始化地图的只读 NCS 与武器采集生成绑定，核对客户端摘要、CRC、名称唯一性、注册顺序与定义长度。两种电台实采切出899ms、举起1200ms、射击间隔800ms。商城物品编号不作为网络武器编号。源码只包含必要布局与行为实现；完整定义和原生采样保存在忽略目录。

连杀进度来自去重的权威敌方死亡。普通三槽沿用当前生命的已校验背包，按成本排序；硬汉的 `modKillstreakShift=-1` 只改变普通成本。达到门槛后，处理器发放独立库存和对应原生动作槽；切到实际持有电台时消耗一次并建立队伍支援，1200ms后切回原枪，同时纠正客户端所选武器和弹药显示。三项普通库存与额外核弹并存，切换不会覆盖其它奖励或原枪附加模式。

采用本地 Alpha／LAN 兼容策略：每项每条命只发一次、每项最多持有一个、死亡保留已获得项并清零本条命进度；重生后可再次达标。换背包时保留仍被选择的已获得项，清除不再选择的项。支援持续30秒，不因调用者死亡终止；同队多个 UAV 重叠时加速，敌队反侦察机阻断雷达，最后一个实例到期后恢复。`modInvalidCounterUav` 的持有者免受反侦察机阻断。以上策略不构成本版官方服务端脚本的恢复结论。

雷达使用本版 PS+0x218／字段82、codec -101、hint2：更新门控后是绝对6位状态，显式发送0清除。bit0启用、bit1阻断、bits2..3扫描模式；普通 UAV 为5，加速为9，阻断在原值上增加2。原生消费者更新扫描相位和敌方标点缓存。状态随历史视角和奖励库存进入回放，不借用当前队伍状态或重复调用。

当前接入范围是原生电台、库存、动作和雷达／干扰状态。空中实体、飞机巡航与击落、各图独立资源绑定、完整空中单位技能交互，以及其它普通奖励尚未完成。原生 Bot 的全部雷达隐身能力呈现仍需核对。

合成回归覆盖死亡去重、3／4杀门槛、硬汉门槛、死亡保留、背包换槽、同队叠加、跨队干扰、30秒边界、核弹并存、附加模式切换、6位协议清零与流对齐、资源错误拒绝。重现检查：

```sh
CARGO_INCREMENTAL=0 sh tools/check.sh
python3 tools/prepare_radars.py --assets <nuke-assets.json> --ncs <net-constants.json> --output <radar-map.json>
```

原生证据位于 `research-output/uav-native-20261014/`。使用最新版 Rust 启动器、标记隔离账号、六个聚集且不移动的敌人、0连杀起始、普通窗口键鼠和只读采样。

实机验收已确认0→3杀 UAV、0→4杀反侦察机的自然门槛、右侧原生图标及库存，4／5按键调用、各消耗一次、切回原枪、UAV扫描相位变化与敌方标点缓存更新、30秒到期清零。反侦察机通过原地敌人正常枪械判伤触发的真实击杀回放确认：敌方历史视角出现原生阻断状态2，本方UAV保持状态5；采样得到102个敌方阻断帧。证据为 `ordinary-native-result.json`、对应只读采样、输入回执和启动器日志。目录未验证的奖励仍不宣称全部验收。

隔离验收可使用核弹资源的 `acceptance_stationary=true` 和 `acceptance_fire_after_msec`：计时从对局开始，在指定时间后由一个无反侦察免疫的敌人使用正常枪械、碰撞与伤害路径开火，位置保持不变。该选项仅在带 `.codol-nuke-acceptance` 的资源及服务数据目录允许，范围1000..600000ms，不进入正常地图配置。此诊断用于敌方视角和回放验收，不作为常规Bot行为。
