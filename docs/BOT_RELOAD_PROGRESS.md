# Bot 第三人称换弹动作

Bot根据实际武器换弹状态8..12播放原生上身换弹节点，保留独立腿部动作，手持枪跟随手部骨骼链接。

准备器从本版 `mp/playeranim.script` 的 `reload` 规则及实际武器的 playerAnimType/weaponclass 选择节点，并要求当前站立和移动分支可以使用同一上身动作。缺失、歧义或不支持的规则拒绝生成。可选 `reload_animation` 兼容旧准备；不会为没有资源证据的旧配置猜编号。

当前三图独立捕获绑定结果：SMG分支581 `pt_reload_stand_auto_mp40`，自动武器分支582 `pt_reload_stand_auto`，Striker所在规则分支584 `pt_reload_stand_rifle`。名称来自本版规则，不凭武器显示名称猜动作；MG4/RPD当前定义同样选择582。资源与原准备SHA记录在 `bot-reload-resource-proof.json`，正常三图配置只增加换弹节点，保留7500分/10分钟。

上身重启位与第一人称动作位独立维护：开始换弹及新的逐发装填阶段重启，相同阶段的重复快照保持；收尾阶段继续上一动作，避免重新播放插弹。补弹已发生但换弹时间未结束时，上身仍保持换弹；退出状态后恢复原开火/待机上身，腿部动作不被清零，重生清理动作生命周期。历史快照直接保留这些节点与重启位。

## 验证

- `bot-reload-check.log`：Rust／Python及fmt／Clippy通过。回归包含收尾衔接及SMG资源准备分支。
- Rust回归实际运行 `Player` 的扣弹、换弹、补弹、ready 状态，验证弹匣换弹期间只启动一次、补弹后仍维持动作、下一次重新启动，以及逐发装填开始/两次插弹/收尾的衔接。不是只给快照手填一个动作编号。
- 正常实机在AK104、M14EBR、G36C等Bot上记录换弹姿态启动。原生状态采样中Bot7共有44帧收到582且原生 torso lerp 同步到582；期间腿部243→395仍能正常变化。约63933ms进入，66728ms离开，随后恢复开火/待机节点，未残留换弹。该局最终回放、前三名与结算完成。
- `bot-reload-live-proof.json`保留采样文件与原生匹配计数。原生已采到的节点为582；581/584已完成资源和状态机回归，尚未获得各自的实机播放片段，不把这一项写成所有枪械视觉验收通过。

此功能接通上身换弹表现，不代表所有武器的弹匣分件、逐帧手部姿势、换弹特长倍率与官方完全一致。更多角色和枪械动作分别复核。
