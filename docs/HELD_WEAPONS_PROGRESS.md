# 第三人称持枪实体

正常对局、尸体、回放和前三名共用真实组合枪显示，运行核心为Rust。角色本身的weapon编号不足以表示组合枪，需独立挂枪实体。

## 实现与本版依据

角色的ES.weapon和clientInfo缓存编号只能描述所持武器。组合枪械还需要独立SCRIPTMOVER实体，由原生构造器拼装枪身、配件和贴图，再挂到`tag_weapon_right`。运行核心仍为Rust，未改客户端或其资源。

| 数据/消费者 | 本版位置 |
| --- | --- |
| SCRIPTMOVER字段表 | 0xc546a0，61项，eType6 |
| 组合世界模型 | 0x501550→0x501320→0x42e6d0，读取组合记录+0xf68部件 |
| 枪械编号 | ES+0x68，字段29，10bit |
| 父实体/挂点 | ES+0xe4，字段18，28bit；low16=父实体+1，bits16..23=动态tag槽 |
| 动态tag | 0x5036e0读取configstring6802+slot；本服务登记slot1=`tag_weapon_right` |
| 角色主枪引用 | clientState+0x114，字段0/11bit，0x52533e复制到clientInfo+0x330 |

字段表与SHA见`fixtures/protocol/held-weapon-3.3.3.3.json`。静态证据位于忽略目录`research-output/ghidra/held-gun-*`与`world-weapon-*`。

枪实体固定占27..53，编号为27+父实体，覆盖玩家/Bot/展示副本0..18和尸体19..26。弹着改为54..1799，击杀栏仍为1800..2045。发送顺序为角色、尸体、挂枪、弹着、击杀栏。

根据实际输出的角色/尸体快照生成挂枪，正常对局、回放和前三名共用同一实现；回放取历史武器。换枪更新原枪实体，死亡移除旧父实体的枪，尸体有自己的枪实体，重生/尸体槽复用按ACK基线重新生成。

完整角色基线不同时塞入所有枪械，后继增量帧补齐。网络历史记录基线是否真的包含挂枪，不能由角色存在推断枪存在。这与既有尸体的完整/增量边界一致，避免最终回放首帧超包。

## 验证与边界

独立字段解码覆盖八种位池起点、生成／换枪／删除／复用、非法编号及训练基线隔离；真实地图单独核对完整角色、挂枪增量和前三名预算。实际对局与尸体已有正确DObj、部件、父实体、tag和clientInfo采样，回放→前三名→结算返回已原生验证。

当前支持主手枪；双持第二把枪、其它手持装备、更多动作与完整官方演出需分别实现或验收。不能从单次DObj实读推断全部近距离画面通过。
